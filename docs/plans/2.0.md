# PiTasker 2.0 — fix, refresh, then the fleet's cron editor

Status: plan, 2026-09-30. Phases P1+P2 in a Claude Code **cloud** session
(branch `feat/2.0-p1p2` from `main`); P3/P4 get their own plan update and
cloud session after P1+P2 are live. Deploy, per-host setup and releases are
done from the CLI (as for PiDeck).

## Goal

PiTasker (pitasker.piapps.dev, piapps, pm2 `pitasker`, v1.0.0) becomes the
one place to see and edit cron across the homelab:

1. **P1 — correct and safe**: fix the bugs below, security hardening, a test
   suite. Release 2.0.0-p1 → **2.0.0** once P2 lands (semver per phase like PiDeck: 2.0.0, 2.1.0 …).
2. **P2 — UI refresh**: the PiDeck 2.0 look (tokens, dark/light, mobile),
   readable schedules, run history.
3. **P3 — read-only fleet view**: every host's crontabs, `/etc/cron.d` and
   systemd timers in one screen.
4. **P4 — fleet editing** of the **zk crontab** on each host through a new,
   separate **PiTasker agent**; root crontab and `/etc/cron.d` stay read-only
   (a later opt-in phase).

## Decisions (operator, 2026-09-30)

- Remote hosts through a **separate PiTasker agent** (own token, own port);
  PiDeck agents stay strictly read-only.
- P4 edits **zk crontabs only**; root + `/etc/cron.d` read-only for now.
- Hosts: the PiDeck fleet: piapps (hub, local), piapps2, piapps3, piapps4,
  hwca-ap02 (production: rollout last, check hwca.de). Not linuxsvr, not DS920 (DSM has no crontab).

## Where we are (recon, 2026-09-30)

Stack: React 18 + Vite + shadcn/ui, Express, Postgres (drizzle, `db:push`,
tables `users`, `tasks`), node-cron + `child_process.exec`, Firebase web
notifications (VITE_FIREBASE_* set), Node 22, ~9.6k LOC. `tsc` clean. **No tests.**
pm2 app `pitasker` from `/home/zk/projects/PiTasker` (building there deploys),
port 5007 on all interfaces, ufw DENY 5007 → reachable only through nginx

Hotfixes already on `main` (2026-09-30):
- `b2e5ca7` logs API (`/api/pitasker-logs`) required no login → now `isAuthenticated`.
- `0b12891` `scheduleTask()` skips `isSystemManaged` tasks: PiTasker ran all
  17 crontab jobs **a second time** with node-cron (in UTC, so daily jobs ran 8 h

### Bugs and debt for P1
1. **Scheduler model**: after hotfix 2 the internal scheduler only runs
   DB-only tasks. Make it explicit and tested: a task is *either* run by the
   system crontab (`isSystemManaged`) *or* by PiTasker, never both; the
   toggle route (`POST /api/tasks/:id/toggle-system-managed`) must
   (un)schedule immediately; internal schedules use the **host's time zone**
   (not hard-coded `"UTC"`), and the UI shows which one runs it.
2. **Stuck state**: 5 tasks show `status=running` since April (ids 46–49, 57),
   one has `last_run` in the future (10-31). Status must come from real runs:
   for crontab-run tasks PiTasker doesn't see runs, so show "run by cron"
   (and, from P2, the last run parsed from the job's log/journal where known)
   instead of a fake status. Reset stale `running` on start.
3. **Crontab writes through a shell** (`echo '…' | crontab -`): replace with
   `execFile("crontab", ["-"])` + stdin; `crontab -l` via execFile too. Before
   every write: save the previous crontab (`~/.local/state/pitasker/crontab-backups/`,
   timestamped, keep 50), write, read back and compare; on mismatch restore.
4. **The hand-curated crontab must survive**: piapps' zk crontab has an audit
   header, section comments and `# DISABLED …` lines. Round-trip tests: import
   + export of an unchanged crontab is **byte-identical**; comments, blank lines,
   env lines (`TZ=`, `MAILTO=`, `PATH=`), `@reboot`/`@daily`, `%` escapes and
   disabled lines are preserved; only PiTasker's own markers are added. Today
   17 active lines exist but only some carry `# PITASKER_ID:` markers:
   find out why and fix (idempotent import, stable ids — see `cd77a22`).
5. **Task runner**: `exec(command, {timeout: 300000})` keeps only stdout *or*
   stderr (`stdout || stderr`) → keep both, capped; record exit code and
   duration; kill the process group on timeout.
6. **npm audit**: 10 vulnerabilities (2 critical, 5 high: ws, qs, body-parser,
   protobufjs via firebase, tar, @grpc). Target 0 for production deps.
   Firebase: keep only if it's really used (check with the operator in the report).
7. **Hardening**: login rate limiting; `helmet`/CSP (script hashes, like
   PiDeck's `CSP_ENFORCE`); session cookie `sameSite: 'none'` → `lax`
   (same origin); `SESSION_SECRET` required at start; `/change-password` rules.
8. **Housekeeping**: one pm2 file (`ecosystem.config.cjs`, settings in `.env`),
   drop `ecosystem.config.js`; move the 9 status docs from the repo root into
   `docs/archive/`; README truthful (memory: 134 MB today, not "<90 MB");
   `CLAUDE.md`/`AGENTS.md` for the repo; a `CHANGELOG.md`.
9. **Migrations**: `db:push` only → drizzle migrations with a baseline (the
   same approach as PiDeck 2.5 M0: mark existing DBs, never re-create).
10. **Tests** (new): vitest unit (crontab parser/serializer round-trips,
   scheduler model, runner, routes incl. auth on **every** `/api` route —
   a test that walks the router and fails on an unauthenticated route),
   Playwright E2E (login, task CRUD, import/export against a **fake crontab**
   binary on PATH, logs widget). Never touch the real crontab in tests.

### P2 — UI refresh
- PiDeck 2.0 design language: theme tokens (dark/light), the same header,
  cards and dialogs, keyboard shortcuts, mobile (390 px) without horizontal scroll, axe-clean.
- Task list: plain-language schedule ("every 5 min", "daily 07:04 Asia/Taipei"),
  next 3 runs, who runs it (cron / PiTasker), last run + exit code + duration,
  output viewer, filters (host from P3, runner, status), search.
- Cron editor: presets + field-by-field builder with live preview and
  validation; warns when a command's script isn't in `/home/zk/bin` or
  isn't committed to bin.git (operator rule: cron-invoked scripts live in
  `/home/zk/bin` and are committed **before** the job goes live).
- Crontab view: the raw crontab with sections as written, PiTasker-managed
  lines highlighted; a diff dialog before every write; backups list with restore.
- Remove unused shadcn components / deps (bundle size reported).

### P3 — read-only fleet view (separate plan update)
All hosts in one screen: zk crontab, root crontab, `/etc/cron.d/*`, systemd
timers (next/last run), grouped per host, searchable; "same job on two hosts"
and "script not in bin.git" hints. Data from the PiTasker agent's read endpoints.

### P4 — fleet editing, zk crontabs (separate plan update)
Security design (to be detailed before building):
- **PiTasker agent**: same codebase, `PITASKER_MODE=agent`, runs as **zk**
  (no root, no sudo), systemd unit with `MemoryMax`; binds to the LAN/tunnel
  IP only (wg-pideck `10.77.0.x` for VPSes), own port, ufw allow **only from
  the hub**; bearer token per host, separate from PiDeck's.
- Write API = **structured operations only** (add / update / enable / disable /
  delete one line, with the expected current crontab hash) — no raw shell, no
  arbitrary file paths. Optimistic concurrency: refused if the crontab changed.
- Every write: backup on the agent, read-back verify, audit line (who, what,
  diff) on hub and agent; restore any backup from the hub.
- Hub UI: diff + typed confirmation for other hosts; hwca-ap02 marked production.
- Opt-in per host (`PITASKER_AGENT_WRITE=on`); read-only agents are the default.

## Tests and gates (every phase)
tsc, vitest, Playwright E2E, `npm audit` (prod) 0, bundle size reported,
no test writes the real crontab, a route-auth test.

verify: crontab byte-identical before/after start, no job runs twice (cron
journal vs PiTasker log for 10 min), login/logs/import/export in the UI.
Then version + CHANGELOG + tag + GH release.
