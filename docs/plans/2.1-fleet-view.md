# PiTasker 2.1 — P3: read-only fleet view

Status: plan, 2026-10-01. Phase P3 of [2.0.md](2.0.md). Built in a Claude
Code **cloud** session on branch `feat/2.1-fleet-view` from `main`; review,
per-host installs, rollout and the release are done from the CLI (as for
2.0 and PiDeck 2.4–2.8). Release: **2.1.0** (P4 = 2.2.0).

## Goal

One screen that shows **everything scheduled on the homelab**: every
host's zk crontab, root crontab, `/etc/crontab`, `/etc/cron.d/*`,
`cron.{hourly,daily,weekly,monthly}` and systemd timers (system + zk user),
with the schedule in plain language in **that host's** time zone, next runs,
last run, and two hints: **"same job on two hosts"** and **"script not in
bin.git"**. Nothing is written anywhere: P3 is read-only end to end.

The remote data comes from a new, small **PiTasker agent**. P4 will add write
routes to the same agent; P3 builds it so that fits (crontab hashes now),
but ships **no write code**, not even disabled.

## Decisions

From 2026-09-30 (unchanged): separate PiTasker agent (own token, own port,
PiDeck agents stay read-only); hosts = piapps (hub, local), piapps2,
piapps3, piapps4, hwca-ap02 (production, last); not linuxsvr, not DS920.

Defaults set in this plan (operator can overrule before the cloud run):
1. **Version 2.1.0**, per-phase minor bumps as in 2.0.md.
2. **Port 5017** on every agent (free on all five hosts; PiDeck agent 5016,
   PiDeck E2E 5018–5020, PiTasker 5007, PiTasker E2E 5027).
3. **Root crontab through a root-owned snapshot unit**, not sudo: the agent
   runs with an empty capability bounding set, so `sudo` can't work from it
   (see Security). No sudoers rule for PiTasker.
4. **No DB migration.** The hub keeps the last good snapshot per host as a
   JSON file in `PITASKER_STATE_DIR/fleet/<host>.json` (0600), so offline
   hosts still show their last data after a restart.
5. **piapps is read in-process** by the hub (same collector module); no
   agent on piapps.
6. **The agent is one bundled file** (`dist/agent.mjs`, all deps inlined, no
   native modules, no node_modules on the host): built on piapps, copied to
   each host. No git clone and no npm on the VPSes (piapps3 has 2 GB RAM and
   ~950 MB swap in use; hwca-ap02 has 1 GB).

- zk is in `adm` on all five hosts (cron journal readable), has **passwordless
  sudo for ALL** everywhere, and user lingering (`Linger=yes`, one user timer each).
- `/var/spool/cron/crontabs` is `drwx-wx--T root:crontab`: `crontab -l` works
  only through the **setgid** `crontab` binary → the agent unit must **not**
  set `NoNewPrivileges=` (it would drop setgid and break `crontab -l`).
- `/etc/crontab` and `/etc/cron.d/*` are 0644 root (certbot, e2scrub_all,
  sysstat on some hosts).
- `systemctl list-timers --all -o json` works on 255 and 259. Keys: `unit`,
  `activates`, `next`, `last` (µs since epoch, 0 = none), `left`, `passed`.
  **`left` and `passed` are not durations** (`left` == `next` on both versions):
  use only `next`/`last`. Schedule expressions aren't in that JSON → one
  `systemctl show -p Id,TimersCalendar,TimersMonotonic <timer…>` call; the
  service's `ExecStart`, `User`, `Result`, `ExecMainStatus` via one
  `systemctl show` call on the activated units. User timers: `systemctl
  --user` with `XDG_RUNTIME_DIR=/run/user/<uid>`.
- Cron journal: `SYSLOG_IDENTIFIER=CRON`, `_SYSTEMD_UNIT=cron.service`,
  `MESSAGE="(zk) CMD (<command>)"` (also `(root) CMD (...)`). Start only, no
  exit code. The existing `server/services/cronSeen.ts` parses this already.
- `/home/zk/bin` is a bin.git replica on every host; replicas can lag
  (hwca-ap02 at `43b21de`, the others at `83bcea9`). piapps2 is bin.git master.
- PiDeck (public, hexawulf/PiDeck) has the patterns to copy (copy, don't
  import): `server/middleware/agentAuth.ts` (bearer token as SHA-256 hash,
  `timingSafeEqual`, 429 limiter), `server/hosts.ts` (hub registry +
  statuses), `server/services/agent-logs/redact.ts` (secret redaction +
  tests), `deploy/systemd/pideck-agent.service.template`, `scripts/install.sh --agent`.

## Architecture

```
browser ─► hub (piapps, pitasker.piapps.dev) GET /api/fleet
             │ local: collector in-process (as zk)
             │ remote: host from PITASKER_HOSTS only · fixed path · Bearer token
             │         5 s timeout · 1 MB cap · JSON validated (zod) · no redirects
             ▼
           agent GET /api/agent/cron   (bind: LAN/tunnel IP only, port 5017,
             │                          ufw allow only from the hub)
             ▼
           collector (shared with the hub): execFile only, fixed argv,
           redaction before anything leaves the host
```

### Agent (`PITASKER_MODE=agent`, entry `server/agent/index.ts` → `dist/agent.mjs`)
- No DB, no session, no UI, no Vite, no task runner or scheduler. Imports
  only the collector, `shared/cron.ts`, `server/crontab/document.ts` and auth.
- Routes (GET only; anything else 404/405):
  - `GET /api/agent/health` → `{ version, host, tz, capabilities: { cron: true, write: false } }`
  - `GET /api/agent/cron` → the snapshot (below).
- Startup refuses to run if: `PITASKER_AGENT_BIND` is missing, `0.0.0.0`/`::`,
  or not an address on this host; `PITASKER_AGENT_TOKEN_SHA256` is missing or
  not 64 hex chars. Port from `PITASKER_AGENT_PORT` (default 5017).
- Collector results cached 30 s; the journal read is capped (stdout limit,
  `--since=-2d`, only `MESSAGE` + timestamp fields); a failure in one source
  goes into `errors[]`, never fails the whole snapshot.
- Targets: idle RSS **< 60 MB**, `MemoryMax=96M` in the unit (installer flag).
  **Review 2026-10-01:** measured on piapps (arm64, Node 22, real data): idle 65 MB,
  steady 94–97 MB after 6–8 collections (plateau, not a leak); x86_64 72–74 MB
  (cloud). V8 heap flags change nothing, `--jitless` crashes → default
  **`MemoryMax=128M`**. The cron journal read moved from `-o json` (7.9 MB on
  piapps, peak 121 MB) to `-o short-unix --grep` (0.8 MB, peak 95 MB).

### Snapshot (shared type in `shared/fleet.ts`, zod-validated on the hub)
```
{ host, tz, generatedAt, agentVersion,
  bin: { head, dirty, path: "/home/zk/bin" } | null,
  sources: [
    { kind: "crontab", owner: "zk"|"root", hash /*sha256 of raw text, for P4*/,
      snapshotAt? /*root: age of the snapshot file*/, entries: Entry[] },
    { kind: "etc-crontab" | "cron.d", file, entries: Entry[] },
    { kind: "run-parts", dir: "cron.daily"…, scripts: string[] },
    { kind: "timer", scope: "system"|"user", unit, activates, calendar[],
      next, last, result, exitStatus, user, command, script? } ],
  errors: [{ source, message }] }

Entry = { id /*stable: source + line text hash*/, line, schedule, user?,
  command /*redacted*/, disabled, env? /*TZ/CRON_TZ in effect*/,
  nextRuns: string[3] /*ISO, computed in the host's TZ / CRON_TZ*/,
  lastRun?: { at, source: "journal"|"logfile" },
  script?: { path, exists, inBin, tracked, dirty } }
```
- Parse crontabs with the existing `server/crontab/document.ts` (it keeps
  comments, env lines, `@reboot`, `%`, `# DISABLED` lines). `/etc/crontab`
  and `cron.d` lines have a user field: extend the parser for that shape
  (system-crontab mode) with round-trip tests.
- `nextRuns` use the **host's** TZ (`timedatectl show -p Timezone --value`,
  fallback `/etc/timezone`, then `TZ`), honouring `CRON_TZ=`/`TZ=` lines.
  `@reboot` → no next run, shown as "at boot".
- `script`: the first word of the command (after `cd …&&`, `bash`/`sh`/`python3`
  wrappers) if it's an absolute path or `~/`/`$HOME/`; `inBin` = under
  `/home/zk/bin`; `tracked`/`dirty` from one `git -C /home/zk/bin ls-files` +
  one `git status --porcelain` per snapshot (not per entry).

### Root crontab without sudo
Installed by the agent installer (and on piapps by the hub setup), root-owned:
- `pitasker-root-cron-snapshot.service` (oneshot, root): `crontab -l -u root`
  → `/var/lib/pitasker/root-crontab` (0640 root:zk, atomic rename; empty +
  marker when root has no crontab).
- `.path` unit: `PathChanged=/var/spool/cron/crontabs` (any crontab change
  refreshes it) + `.timer` every 15 min as a fallback.
- The agent reads that file and reports `snapshotAt`; the UI shows its age.

### Hub
- Config (mirrors PiDeck): `PITASKER_HOSTS=piapps2=http://192.168.50.120:5017,piapps4=http://10.77.0.4:5017,…`,
  `PITASKER_HOST_TOKEN_<ID>` (upper-case, `-`→`_`), `PITASKER_HOST_LABELS`,
  `PITASKER_HOST_PRODUCTION=hwca-ap02`. URLs: http(s), no credentials, no
  path; ids `[a-z0-9-]+`. Empty `PITASKER_HOSTS` = local only (the page still works).
- Routes (all `isAuthenticated`; the route-auth test covers them):
  - `GET /api/fleet` → hosts (status `online|offline|auth-error|version-mismatch|stale`,
    lastSeen, version, tz, bin head) + all entries + cross-host hints.
  - `GET /api/fleet/:host?refresh=1` → one host, bypassing the 60 s cache.
- Never forwards cookies or client headers; never returns agent text on errors
  (just the status). Concurrent fetches, one slow host never blocks the others.
- **Hints** (computed on the hub over all snapshots):
  - *same job on two hosts*: normalized command equal (whitespace, `~`/`$HOME`
    → `/home/zk`, output redirections stripped) or same bin script path.
  - *script not in bin.git*: zk crontab / zk user timer / root entries whose
    script is under `/home/zk` but not in `/home/zk/bin`, untracked, dirty,
    or missing. System packages (certbot, e2scrub, sysstat) don't get this hint.
  - *bin replica differs*: host's `/home/zk/bin` HEAD ≠ piapps2's (master).
  - *disabled*: `# DISABLED` lines shown muted, not hidden.
- The existing Tasks/Crontab pages stay as they are (piapps editing);
  the Fleet page links to them for piapps zk entries.

### UI — Fleet page (PiDeck 2.0 design language, tokens only)
- Nav item "Fleet" + the next free `g`-shortcut. Host chips on top: status
  dot, label, TZ, version, bin HEAD, "production" badge on hwca-ap02, last
  seen; refresh button.
- Two views: **By host** (collapsible host sections, grouped by source) and
  **All jobs** (one table: host, source, schedule in plain language + host TZ,
  next run in host time with the hub-local time in a tooltip, last run, command, hints).
- Filters: host, source (zk / root / system / timer), hint; search over
  command and schedule; URL query keeps filters.
- Offline host: last snapshot, greyed, "as of <time>". Errors per source inline.
- 390 px: cards instead of the table, no horizontal scroll; axe clean.
- No edit, delete, run or toggle controls anywhere on this page.

## Security (P3)

- Agent: bearer token (32 random bytes, hex) stored on the agent only as
  SHA-256; `timingSafeEqual`; 429 after repeated failures; token never logged.
- Network: bind to the LAN IP (piapps2) or the wg-pideck IP (VPSes); ufw
  allow 5017 **only from the hub** (192.168.50.102 on the LAN; 10.77.0.1 on
  `wg-pideck`); nothing new is reachable from the internet.
- **zk has passwordless sudo on every host**, so a compromised agent running
  as zk could become root. The unit blocks that: `CapabilityBoundingSet=`
  (empty) + `AmbientCapabilities=` → sudo can't change uid, while setgid
  `crontab -l` still works. Plus `ProtectSystem=strict`, `ProtectHome=read-only`,
  `PrivateTmp=yes`, `ReadWritePaths=` none except its state dir, `MemoryMax`,
  `After=`/`Wants=` the tunnel on VPSes. Verified per host at rollout (below).
  **Checked 2026-10-01 on piapps2** with `systemd-run -p User=zk -p CapabilityBoundingSet=
  -p ProtectSystem=strict -p ProtectHome=read-only`: `sudo -n true` fails (sudo-rs
  panics "could not restore to saved user id", exit 101), `crontab -l` reads all
  133 lines, the cron journal and system + user timers are readable; with
  `NoNewPrivileges=yes` `crontab -l` fails (`fopen: Permission denied`).
- execFile with fixed argv only (`crontab -l`, `systemctl … show/list-timers`,
  `journalctl …`, `git -C /home/zk/bin …`, `timedatectl`); no shell, no
  paths from requests; the agent has **no request parameters at all**.
- **Redaction on the agent, before data leaves the host** (and the same for
  the local collector): PiDeck's rules for commands, plus env lines in
  crontabs whose name ends in KEY|TOKEN|SECRET|PASS|PASSWORD|AUTH → value
  `[REDACTED]`. The hash in `sources[].hash` is of the raw text (P4 needs it),
  never the raw text itself.
- Jobs' environment and `process.env` never appear in any response.

## Installer — `scripts/install-agent.sh`

Bash, `set -euo pipefail`, metadata header, logs to `~/logs/pitasker-agent-install-<ts>.log`,
colour with non-interactive fallback, **`--dry-run`** prints every action.
- `--bind IP` (required), `--port 5017`, `--ufw-allow-from IP`,
  `--ufw-interface IF`, `--after UNIT` (e.g. `wg-quick@wg-pideck`),
  `--memory-max 128M` (default), `--bundle PATH` (the copied `agent.mjs`), `--update`
  (swap bundle, keep `.env`, keep `agent.mjs.prev`), `--rollback`, `--uninstall`.
- Installs to `/home/zk/pitasker-agent/` (`agent.mjs`, `.build-commit`,
  `.env` 0600), renders the unit (checked with `systemd-analyze verify`), installs
  the root-snapshot units, adds the ufw rule, records what it did in
  `~/.config/pitasker/install-agent` (uninstall removes exactly that).
- Token: generated on first install; hash → `.env`; plain token → `~/.config/pitasker/agent-token`
  (0600) once, for the operator to move to the hub `.env` and `shred`.
- Installer tests with stubbed `systemctl`/`ufw`/`sudo`/`systemd-analyze`
  (PiDeck style), incl. dry-run writes nothing and uninstall is exact.
