# PiTasker 2.1 — P3: read-only fleet view

Status: shipped in 2.1.0 (design record). Phase P3 of [2.0.md](2.0.md).
Host names and addresses below are placeholders (`hub`, `host-a`…,
documentation IP ranges).

## Goal

One screen that shows **everything scheduled across a small fleet**: every
host's user crontab, root crontab, `/etc/crontab`, `/etc/cron.d/*`,
`cron.{hourly,daily,weekly,monthly}` and systemd timers (system + user),
with the schedule in plain language in **that host's** time zone, next runs,
last run, and two hints: **"same job on two hosts"** and **"script not in
bin.git"**. Nothing is written anywhere: P3 is read-only end to end.

The remote data comes from a small **PiTasker agent**. A later phase may add
write routes to the same agent; P3 builds it so that fits (crontab hashes
now), but ships **no write code**, not even disabled.

## Decisions

1. **Separate PiTasker agent** (own token, own port); other monitoring agents
   on the hosts stay read-only and unrelated.
2. **Port 5017** on every agent.
3. **Root crontab through a root-owned snapshot unit**, not sudo: the agent
   runs with an empty capability bounding set, so `sudo` can't work from it
   (see Security). No sudoers rule for PiTasker.
4. **No DB migration.** The hub keeps the last good snapshot per host as a
   JSON file in `PITASKER_STATE_DIR/fleet/<host>.json` (0600), so offline
   hosts still show their last data after a restart.
5. **The hub reads its own host in-process** (same collector module); no
   agent on the hub.
6. **The agent is one bundled file** (`dist/agent.mjs`, all deps inlined, no
   native modules, no node_modules on the host): built on the hub, copied to
   each host. No git clone and no npm on small VPSes.

## Platform notes

- The agent user needs read access to the cron journal (`adm` group).
- `/var/spool/cron/crontabs` is `drwx-wx--T root:crontab`: `crontab -l` works
  only through the **setgid** `crontab` binary → the agent unit must **not**
  set `NoNewPrivileges=` (it would drop setgid and break `crontab -l`).
- `systemctl list-timers --all -o json` works on systemd 255 and 259. Keys:
  `unit`, `activates`, `next`, `last` (µs since epoch, 0 = none), `left`,
  `passed`. **`left` and `passed` are not durations** (`left` == `next` on
  both versions): use only `next`/`last`. Schedule expressions aren't in that
  JSON → one `systemctl show -p Id,TimersCalendar,TimersMonotonic <timer…>`
  call; the service's `ExecStart`, `User`, `Result`, `ExecMainStatus` via one
  `systemctl show` call on the activated units. User timers: `systemctl
  --user` with `XDG_RUNTIME_DIR=/run/user/<uid>`.
- Cron journal: `SYSLOG_IDENTIFIER=CRON`, `MESSAGE="(<user>) CMD (<command>)"`.
  Start only, no exit code (`server/services/cronSeen.ts` parses it).
- The bin directory (`PITASKER_BIN_DIR`) is a git replica on every host;
  replicas can lag behind the master.

## Architecture

```
browser ─► hub  GET /api/fleet
             │ local: collector in-process
             │ remote: host from PITASKER_HOSTS only · fixed path · Bearer token
             │         5 s timeout · 1 MB cap · JSON validated (zod) · no redirects
             ▼
           agent GET /api/agent/cron   (bind: LAN/tunnel IP only, port 5017,
             │                          firewall: allow only from the hub)
             ▼
           collector (shared with the hub): execFile only, fixed argv,
           redaction before anything leaves the host
```

### Agent (`PITASKER_MODE=agent`, entry `server/agent/index.ts` → `dist/agent.mjs`)
- No DB, no session, no UI, no Vite, no task runner or scheduler. Imports
  only the collector, `shared/cron.ts`, `server/crontab/document.ts` and auth.
- Routes (GET only; anything else 404/405):
  - `GET /api/agent/health` → `{ version, host, tz, capabilities: { cron: true, write: false } }`
  - `GET /api/agent/cron` → the snapshot (below).
- Startup refuses to run if: `PITASKER_AGENT_BIND` is missing, `0.0.0.0`/`::`,
  or not an address on this host; `PITASKER_AGENT_TOKEN_SHA256` is missing or
  not 64 hex chars. Port from `PITASKER_AGENT_PORT` (default 5017).
- Collector results cached 30 s; the journal read is capped (stdout limit,
  `--since=-2d`, `-o short-unix --grep`); a failure in one source goes into
  `errors[]`, never fails the whole snapshot.
- Memory: steady RSS about 95 MB on arm64 with real data (a plateau, not a
  leak) → default **`MemoryMax=128M`** in the unit.

### Snapshot (shared type in `shared/fleet.ts`, zod-validated on the hub)
```
{ host, tz, generatedAt, agentVersion,
  bin: { head, dirty, path } | null,
  sources: [
    { kind: "crontab", owner: "<user>"|"root", hash /*sha256 of raw text*/,
      snapshotAt? /*root: age of the snapshot file*/, entries: Entry[] },
    { kind: "etc-crontab" | "cron.d", file, entries: Entry[] },
    { kind: "run-parts", dir: "cron.daily"…, scripts: string[] },
    { kind: "timer", scope: "system"|"user", unit, activates, calendar[],
      next, last, result, exitStatus, user, command, script? } ],
  errors: [{ source, message }] }

Entry = { id /*stable: source + line text hash*/, line, schedule, user?,
  command /*redacted*/, disabled, env? /*TZ/CRON_TZ in effect*/,
  nextRuns: string[3] /*ISO, computed in the host's TZ / CRON_TZ*/,
  lastRun?: { at, source: "journal"|"logfile" },
  script?: { path, exists, inBin, tracked, dirty } }
```
- Crontabs are parsed with `server/crontab/document.ts` (it keeps comments,
  env lines, `@reboot`, `%`, `# DISABLED` lines), extended with a
  system-crontab mode for the user field of `/etc/crontab` and `cron.d`.
- `nextRuns` use the **host's** TZ (`timedatectl show -p Timezone --value`,
  fallback `/etc/timezone`, then `TZ`), honouring `CRON_TZ=`/`TZ=` lines.
  `@reboot` → no next run, shown as "at boot".
- `script`: the first word of the command (after `cd …&&`, `bash`/`sh`/`python3`
  wrappers) if it's an absolute path or `~/`/`$HOME/`; `inBin` = under the bin
  directory; `tracked`/`dirty` from one `git ls-files` + one
  `git status --porcelain` per snapshot (not per entry).

### Root crontab without sudo
Installed by the agent installer (and on the hub by its setup), root-owned:
- `pitasker-root-cron-snapshot.service` (oneshot, root): `crontab -l -u root`
  → `/var/lib/pitasker/root-crontab` (0640, atomic rename; empty + marker
  when root has no crontab).
- `.path` unit: `PathChanged=/var/spool/cron/crontabs` (any crontab change
  refreshes it) + `.timer` every 15 min as a fallback.
- The agent reads that file and reports `snapshotAt`; the UI shows its age.

### Hub
- Config: `PITASKER_HOSTS=host-a=http://192.0.2.10:5017,host-b=http://198.51.100.4:5017`,
  `PITASKER_HOST_TOKEN_<ID>` (upper-case, `-`→`_`), `PITASKER_HOST_LABELS`,
  `PITASKER_HOST_PRODUCTION=<id>`. URLs: http(s), no credentials, no path;
  ids `[a-z0-9-]+`. Empty `PITASKER_HOSTS` = local only (the page still works).
- Routes (all `isAuthenticated`; the route-auth test covers them):
  - `GET /api/fleet` → hosts (status `online|offline|auth-error|version-mismatch|stale`,
    lastSeen, version, tz, bin head) + all entries + cross-host hints.
  - `GET /api/fleet/:host?refresh=1` → one host, bypassing the 60 s cache.
- Never forwards cookies or client headers; never returns agent text on errors
  (just the status). Concurrent fetches, one slow host never blocks the others.
- **Hints** (computed on the hub over all snapshots):
  - *same job on two hosts*: normalized command equal (whitespace, `~`/`$HOME`
    → the home directory, output redirections stripped) or same bin script path.
  - *script not in bin.git*: user crontab / user timer / root entries whose
    script is under the home directory but not in the bin directory,
    untracked, dirty, or missing. System packages (certbot, e2scrub, sysstat)
    don't get this hint.
  - *bin replica differs*: a host's bin HEAD ≠ the master's (`PITASKER_BIN_MASTER`).
  - *disabled*: `# DISABLED` lines shown muted, not hidden.
- The Tasks/Crontab pages stay as they are (editing the hub's own crontab);
  the Fleet page links to them for the hub's user entries.

### UI — Fleet page (tokens only)
- Nav item "Fleet" + a `g`-shortcut. Host chips on top: status dot, label,
  TZ, version, bin HEAD, "production" badge, last seen; refresh button.
- Two views: **By host** (collapsible host sections, grouped by source) and
  **All jobs** (one table: host, source, schedule in plain language + host TZ,
  next run in host time with the hub-local time in a tooltip, last run, command, hints).
- Filters: host, source (user / root / system / timer), hint; search over
  command and schedule; URL query keeps filters.
- Offline host: last snapshot, greyed, "as of <time>". Errors per source inline.
- 390 px: cards instead of the table, no horizontal scroll; axe clean.
- No edit, delete, run or toggle controls anywhere on this page.

## Security (P3)

- Agent: bearer token (32 random bytes, hex) stored on the agent only as
  SHA-256; `timingSafeEqual`; 429 after repeated failures; token never logged.
- Network: bind to a LAN or tunnel IP, never `0.0.0.0`; the firewall allows
  port 5017 **only from the hub**; nothing new is reachable from the internet.
- **Assume the agent user can sudo.** The unit blocks privilege gain anyway:
  `CapabilityBoundingSet=` (empty) + `AmbientCapabilities=` → sudo can't
  change uid, while setgid `crontab -l` still works. Plus `ProtectSystem=strict`,
  `ProtectHome=read-only`, `PrivateTmp=yes`, no `ReadWritePaths=` except its
  state dir, `MemoryMax`, `After=`/`Wants=` the tunnel unit where there is one.
  Check per host with `systemd-run -p User=<user> -p CapabilityBoundingSet=
  -p ProtectSystem=strict -p ProtectHome=read-only`: `sudo -n true` must fail
  while `crontab -l` works; with `NoNewPrivileges=yes` `crontab -l` fails.
- execFile with fixed argv only (`crontab -l`, `systemctl … show/list-timers`,
  `journalctl …`, `git -C <bin> …`, `timedatectl`); no shell, no paths from
  requests; the agent has **no request parameters at all**.
- **Redaction on the agent, before data leaves the host** (and the same for
  the local collector): rules for secrets in commands, plus env lines in
  crontabs whose name ends in KEY|TOKEN|SECRET|PASS|PASSWORD|AUTH → value
  `[REDACTED]`. `sources[].hash` is of the raw text, never the raw text itself.
- Jobs' environment and `process.env` never appear in any response.

## Installer — `scripts/install-agent.sh`

Bash, `set -euo pipefail`, metadata header, logs to `~/logs/`, colour with a
non-interactive fallback, **`--dry-run`** prints every action.
- `--bind IP` (required), `--port 5017`, `--ufw-allow-from IP`,
  `--ufw-interface IF`, `--after UNIT` (e.g. `wg-quick@wg0.service`),
  `--memory-max 128M` (default), `--bundle PATH` (the copied `agent.mjs`),
  `--update` (swap bundle, keep `.env`, keep `agent.mjs.prev`), `--rollback`,
  `--uninstall`.
- Installs to `~/pitasker-agent/` (`agent.mjs`, `.build-commit`, `.env` 0600),
  renders the unit (checked with `systemd-analyze verify`), installs the
  root-snapshot units, adds the firewall rule, records what it did in
  `~/.config/pitasker/install-agent` (uninstall removes exactly that).
- Token: generated on first install; hash → `.env`; plain token →
  `~/.config/pitasker/agent-token` (0600) once, for the operator to move to
  the hub `.env` and `shred`.
- Installer tests with stubbed `systemctl`/`ufw`/`sudo`/`systemd-analyze`,
  incl. dry-run writes nothing and uninstall is exact.

## Tests and gates

tsc, `check:theme`, vitest, Playwright E2E, `npm audit --omit=dev` 0, bundle
sizes (client + `dist/agent.mjs`) reported; no test touches the real crontab,
systemctl, journal or `/etc`.
- Fakes on PATH: `crontab`, `systemctl`, `journalctl`, `timedatectl`;
  fixture `/etc/crontab`, `cron.d`, run-parts dirs, root snapshot file and a
  scratch git repo for the bin directory — all paths via config
  (`PITASKER_ETC_DIR`, `PITASKER_ROOT_CRON_SNAPSHOT`, `PITASKER_BIN_DIR`),
  with the VITEST/PITASKER_E2E guards against real paths.
- Fixtures use the real shapes above (systemd 255 **and** 259 timer JSON with
  the `left`/`passed` quirk, cron journal lines, four time zones incl. a DST
  zone).
- Unit: parser round-trips for system-crontab lines; next runs per TZ and
  `CRON_TZ`; script detection; hints; redaction (secrets in commands, env
  lines, URLs; no false positives); snapshot schema; agent startup refusals;
  auth (401/429, only GET, no params).
- E2E: hub + two agents in agent mode on fixture data + one host pointing at
  a closed port (offline) + one with a wrong token (auth-error): Fleet page,
  both views, filters, search, hints, offline host from the saved snapshot,
  390 px, axe.

## Rollout outline

Hub first (backups, root-snapshot units, build, restart; the Fleet page shows
the hub only), then one agent host at a time, production host last. For each:
install with `--dry-run` first, move the token to the hub `.env`, check 200
with the token from the hub, 401 without, a timeout from any other machine,
the `sudo -n true` refusal, and RSS. Crontab hashes must be unchanged
everywhere at the end.
